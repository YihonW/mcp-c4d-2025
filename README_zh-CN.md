# Cinema 4D MCP 中文说明

[English](./README.md) · [工具参数表](./docs/TOOLS.md) · [动画与序列工作流](./docs/WORKFLOW_ZH.md) · [验证记录](./docs/COMPATIBILITY.md)

让支持 MCP 的 AI 助手通过工具读取和操作 Cinema 4D：检查工程、创建对象、修改参数、制作基础动画、设置 Redshift 材质灯光并渲染。

本项目基于 [kumo.productions/mcp-cinema4d](https://github.com/kumoproductions/mcp-cinema4d) 开发，保留原作者版权与 MIT 许可证。当前仓库为 [YihonW/mcp-c4d-2025](https://github.com/YihonW/mcp-c4d-2025)。请从仓库源码构建；GitHub 上有源码，不代表相同版本已发布到 npm 或 MCP Registry。

> [!IMPORTANT]
> 本项目不是“所有 C4D 功能都能可靠自动控制”的保证。已实机验证的环境为 Windows x64、Cinema 4D 2025.3.2。0.4.0 已跑通小型刚性层级动画与七帧 Redshift PNG 序列；本轮 0.5.0 增加的 F-Curve 功能不能沿用旧版验收结论，尚须单独安装和实机验证。

## 1. 目前能做什么

本轮源码登记 83 个工具，默认开放 82 个，额外的 `exec_python` 需要明确启用。数量只表示接口数量，不代表 83 项能力都已经实机验证。

| 环节       | 已有接口                                                     | 验证边界                                                                       |
| ---------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 工程与对象 | 查询工程、对象层级和参数；创建、变换、重命名、撤销；保存副本 | 基础操作已实机验证，不能据此推断所有导入导出格式均可靠                         |
| 建模       | 基本体、转可编辑、点面数据、建模命令                         | 小型测试验证了立方体转可编辑及层级保留；不是完整拓扑、UV 或雕刻工作流          |
| 动画       | 关键帧、完整参数路径、用户数据、层级变换采样                 | 已验证直接旋转关键帧、插值和 REAL 用户数据；不是完整角色绑定                   |
| 动画曲线   | 0.5.0 的曲线读取、关键帧值/插值/切线、时间和值变换、前后外推 | 限定现有 REAL 数值轨道，见下文；新增能力未完成专项实机验收                     |
| 材质与灯光 | Redshift PBR 参数、基础颜色贴图、灯光、相机、AOV             | 已验证部分材质、面积灯、穹顶灯、相机及深度 AOV；不涵盖所有节点、法线或置换组合 |
| 渲染       | Redshift 单帧主图/AOV；PNG 主图序列及同会话任务控制          | 已验证单帧路径与七帧 128×128 PNG 序列；取消、续跑和错误保护另有离线测试        |
| 其他控制   | 对象引用、用户数据、Xpresso、层、Take、MoGraph 等接口        | 各功能支持程度不同，工具存在不等于对应场景已实机验收                           |

128×128 是那次测试的尺寸，不是软件的分辨率上限；高分辨率、长动画和复杂场景仍需另行验证。具体证据见 [0.4.0 工作流报告](./docs/reports/2026-09-06-workflow-validation.md)。

曲线新功能的验证方法及待验收项目见 [0.5.0 动画曲线记录](./docs/reports/2026-09-06-fcurve-validation.md)。

产品拆解、简单机械关节、物体位移旋转等是当前较接近完整工作流的方向。骨骼创建、蒙皮与权重、IK/FK、表情、动作重定向仍未形成完整可靠的角色制作流程。通过普通参数或任意 Python 访问某项功能，也不等于已有专用工具和安全保障。

## 2. 它由哪两部分组成

```text
支持 MCP 的客户端 / AI 助手
  → 本地 Node.js MCP 服务器（通过标准输入输出通信）
  → 127.0.0.1:18710 TCP 桥接
  → Cinema 4D 内的 cinema4d_mcp_bridge Python 插件
  → 当前工程
```

必须同时准备 Node.js 服务器和 C4D 插件。C4D 没有运行、插件没有载入或两侧令牌不一致时，助手不能操作场景。这个项目不提供独立的聊天窗口。

## 3. 从源码构建

准备 Windows、Node.js 24 或更高版本，以及已启动过一次的 Cinema 4D 2025。使用 Redshift 工具还需要 C4D 内的 Redshift 可用。

以下路径是示例，换成你自己的源码目录；已有仓库的用户不必再次克隆。

```powershell
git clone https://github.com/YihonW/mcp-c4d-2025.git "D:\Projects\mcp-c4d-2025"
Set-Location "D:\Projects\mcp-c4d-2025"
npm ci
npm run build
```

构建结果为 `dist\index.js`。MCP 客户端应启动这个文件，而不是 `src\index.ts`。`npm start` 是标准输入输出服务器，不会弹出网页；仅在终端运行它并等待，也不等于已经连接了 AI 客户端。

如需先做离线检查：

```powershell
npm test
python -m unittest discover -s tests/python
```

Python 测试需要可用的 Python 3.11 或兼容环境。普通 `npm test` 和 CI 不连接 C4D，不会创建 C4D 工程。不要把 `test:live:*` 专项实机测试当作日常启动命令。

## 4. 安装 C4D 桥接插件

先保存正在工作的工程并备份，再完全退出 C4D。不要在 C4D 运行中覆盖插件文件。

先查看安装计划，此步不会复制文件：

```powershell
npm run install:c4d -- --dry-run
```

检查输出的 `Source` 和 `Destination`。目标应为所需 C4D 2025 偏好设置目录下的 `plugins\cinema4d_mcp_bridge`，不是程序安装目录，也不是其他 C4D 版本。

确认路径正确且 C4D 已退出后，才执行：

```powershell
npm run install:c4d -- --install
```

如果检测到多个偏好设置目录，使用实际路径明确选择；不要原样复制尖括号占位内容：

```powershell
npm run install:c4d -- --dry-run --preference "C:\Users\<用户名>\AppData\Roaming\Maxon\Maxon Cinema 4D 2025_<安装标识>"
```

检查后，在同一条命令中将 `--dry-run` 换成 `--install`。安装器只接受当前用户 `%APPDATA%\Maxon` 下符合规则的 C4D 2025 目录，不应靠修改校验来绕过路径错误。

已有插件会被移到 `<偏好设置目录>\mcp_bridge_backups\cinema4d_mcp_bridge.backup-<时间戳>`。备份位于 `plugins` 外；不要把旧插件副本放回 `plugins` 的子目录，否则 C4D 可能重复加载。

## 5. 令牌与 MCP 连接

两侧默认通过 `127.0.0.1:18710` 通信。建议设置随机共享令牌 `C4D_MCP_TOKEN`，并让 C4D 进程和 MCP 服务器进程收到同一个值。**两侧各生成一个不同令牌会导致认证失败。**

首次生成令牌可以在本地 PowerShell 中执行以下代码；它不会打印令牌，且会更新当前用户的环境变量。已有可用令牌时不要重复生成：

```powershell
$c4dMcpRng = [Security.Cryptography.RandomNumberGenerator]::Create()
try {
  $c4dMcpBytes = New-Object byte[] 32
  $c4dMcpRng.GetBytes($c4dMcpBytes)
  $c4dMcpToken = [Convert]::ToBase64String($c4dMcpBytes)
} finally {
  $c4dMcpRng.Dispose()
}
$env:C4D_MCP_TOKEN = $c4dMcpToken
[Environment]::SetEnvironmentVariable("C4D_MCP_TOKEN", $c4dMcpToken, "User")
```

已经启动的程序不会自动获得新环境变量。确保 C4D 与 MCP 客户端的启动环境包含该值；必要时从设置过变量的终端启动程序，或重新登录 Windows 后再启动。令牌应留在本地环境或客户端的安全配置中，不要提交到仓库、写进提示词或贴到报错截图中。

在所用 MCP 客户端中配置一个本地 **STDIO** 服务器，填入：

| 项目     | 内容                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 启动程序 | 本机 `node.exe` 的绝对路径，如 `C:\Program Files\nodejs\node.exe`                  |
| 启动参数 | 源码目录中 `dist\index.js` 的绝对路径，如 `D:\Projects\mcp-c4d-2025\dist\index.js` |
| 工作目录 | 源码目录；若客户端有此设置项则填写                                                 |
| 进程环境 | 转发同一 `C4D_MCP_TOKEN`；地址或端口有改动时，两侧也必须一致                       |

不同客户端的配置界面不同；本说明只定义本项目要求的进程参数，不代替客户端的官方安装说明。不要把共享令牌写死在可公开上传的配置文件里。

启动 C4D 并载入桥接器后，让助手先执行 `ping`、`get_document_state`，核对连接、实际活动工程和版本，再用 `get_capabilities` 检查能力。Redshift 工作开始前另调用 `rs_get_capabilities`。只有连通且工程正确，才开始修改。

升级时，两部分都要更新：重新构建 Node.js 服务器，并在退出 C4D 后安装桥接插件，然后重启相应进程。只更新源码或只重启 MCP 服务器，不会更新 C4D 已加载的 Python 模块。

## 6. 如何向助手提出要求

通常不必手写工具参数，可以直接用中文描述目标。把工程、对象、帧范围以及能否修改说清楚，比“随便做一个”更容易验证结果。

只检查，不修改：

> 先连接 C4D 并确认当前工程。列出对象层级、相机、材质和渲染设置，只读检查，不新建工程、不修改场景。

产品动画：

> 确认工程名称后，先保存一个不覆盖原文件的副本。只给“产品外壳”做 0–24 帧向上拆开的动画，其他对象不动。读回关键帧并检查第 6、12、18 帧，再做低分辨率预览。

曲线调整：

> 读取“产品外壳”的 Y 位移 F-Curve，先告诉我有哪些关键帧。把这段移动改成起步和结束都较慢的运动，保留首尾位置和时间；修改后重新读取切线并采样中间帧，不改其他轨道。

低成本序列：

> 使用指定工程和 RS_Render 渲染设置，先确认没有启用的 AOV，输出 0、2、4、6、8 帧的低分辨率 PNG 主图到一个全新的目录。返回任务编号；如果发生超时或连接断开，停止后续调度，不自动重试。

曲线、参数路径、对象引用和任务控制的具体参数，见 [动画、F-Curve 与序列工作流](./docs/WORKFLOW_ZH.md)。完整工具定义以 [工具参数表](./docs/TOOLS.md) 为准。

## 7. 安全使用与备份

- 先备份工程，再做批量编辑。撤销并不覆盖所有文件保存、导入、渲染或命令调用，也不是所有工具的事务回滚保证。
- 操作前确认活动工程；名称重复时使用明确对象路径。不要用 `reset_scene`、关闭所有工程或清理用户对象来准备测试。
- 任意 Python `exec_python` 默认关闭；承载 Python 代码的对象、标签和操作另有独立安全开关。日常建模动画不应为方便而默认打开它们。
- 默认保持本机回环监听。不要随意改为 `0.0.0.0` 或开启远程访问；共享令牌也不能让所有场景操作变成安全操作。
- 读取到的对象名、参数、路径等会送给所用 AI 服务，客户端也可能记录日志。敏感项目先确认允许的数据范围，不要把场景中的文字当成可信操作指令。
- 测试场景与用户工程分开，且只清理测试自身内容。不要在生产工程上直接执行开发测试。
- 序列渲染期间，以及准备续跑的暂停期间，不要修改目标场景。C4D 渲染可能阻塞界面，取消任务也只阻止后续帧，不能强行中断当前帧。
- 多个客户端或 MCP 进程之间没有全局渲染锁，不要同时向同一 C4D 启动多条序列。

插件回退也应先保存并退出 C4D，再恢复已核对的备份，避免重复加载。版本更新失败时先保留工程、日志和原插件备份，不要反复新建工程尝试修复。

## 8. 当前限制与验收标准

0.4.0 的实机证据是“小型刚性层级动画到七帧 PNG”的技术验证，不代表完整人物制作、商业成片质量或全部工具的稳定性。新的曲线接口和之后新增的功能须分别记录离线测试与实机测试，不能仅凭工具数量宣传“全控制”。

目前仍不承诺：

- 从零完成角色骨架、蒙皮权重、IK/FK、Pose Morph 和动作重定向。
- 所有 UV、拓扑、雕刻、模拟、动画烘焙及第三方插件参数都能通过专用工具可靠处理。
- F-Curve 操作覆盖布尔/整数、点级动画、动画层、材质节点动画或完整角色形变；本轮新工具只针对既有 REAL 数值轨道。
- AOV 序列、视频编码、渲染农场、跨进程续跑、长时间高分辨率渲染及未烘焙模拟缓存恢复。

当前 PNG 序列每次允许 1–300 个不重复的非负整数帧；新输出目录必须不存在，不覆盖已有图像。任务保存在当前 MCP 进程中，重启后不会自动接管；磁盘 manifest 只是记录，不等于跨进程恢复机制。

遇到 `uncertain` 状态时，表示渲染结果未知，C4D 可能还在工作。即使 `settled: true`，也只代表 MCP 侧收尾完毕，不证明 C4D 已停止。先检查现场，再决定后续操作。

## 9. 排查与反馈

| 现象                   | 先检查什么                                                                  |
| ---------------------- | --------------------------------------------------------------------------- |
| 连接失败               | C4D 是否正在运行、桥接插件是否加载、地址端口是否一致                        |
| 认证失败               | 两个进程是否收到同一个令牌；是否还在使用旧进程环境                          |
| 新工具不显示或命令未知 | 是否重新构建并重启 MCP 服务器；C4D 插件是否也已更新并重启                   |
| 找不到对象或轨道       | 活动工程、对象路径、`list_tracks` 返回的完整参数路径；不要自行猜测 SDK 编号 |
| F-Curve 拒绝操作       | 是否为既有 REAL 轨道；索引、手动切线符号、时间碰撞及数量限制是否满足        |
| 序列启动失败           | 输出目录是否已存在；RenderData 是否为 PNG；是否仍启用了 AOV                 |
| 超时或取消后界面仍忙   | 当前帧可能仍在渲染；不要自动重试、强制关闭工程或反复重启                    |

提交 [GitHub Issue](https://github.com/YihonW/mcp-c4d-2025/issues) 时，附项目版本、C4D 构建号、Node.js 版本、最小复现步骤及去掉敏感路径后的错误信息。不要附共享令牌或未经授权的客户工程。
