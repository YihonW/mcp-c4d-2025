# Cinema 4D MCP：动画、F-Curve 与序列渲染

[中文完整入门](../README_zh-CN.md) · [工具参数表](./TOOLS.md) · [验证范围](./COMPATIBILITY.md)

这个项目连接 MCP 客户端与 Cinema 4D 内的 Python 桥接器。目标版本是 Windows 上的 Cinema 4D 2025.3.2。它不是“所有按钮都已支持”的保证；实际验收范围见 [COMPATIBILITY.md](./COMPATIBILITY.md)。

## 0.4.0 新增内容

- 动画工具接受完整 `path`，可以给数值、开关及向量分量的用户数据控制器打关键帧；旧 `param_id` + `component` 调用仍保留。
- `list_tracks` 返回可直接回传的完整路径；读取、删除关键帧及轨道按同一路径定位，不混淆不同用户数据槽位。
- `set_params` 新增 `{ "link": handle }` 与 `{ "link": null }`，用来设置或清空真实的对象引用参数。所有引用预检通过后才开始写入；仍须检查返回的 `errors`，撤销组不等于所有运行时错误自动回滚。
- `rs_render` 新增明确 `frame`，渲染后恢复时间与活动渲染设置。
- `rs_render_sequence`、`rs_sequence_status`、`rs_sequence_control` 提供有上限的 PNG 主图序列、进度、停止后续帧及同会话续跑。

## 如何向助手提出制作要求

可以直接描述目标，例如：

> 先读取工程状态并保存副本。在指定测试工程中搭建一个两节机械臂，给关节做 0–24 帧旋转动画；检查中间帧，再设置 Redshift 材质、灯光和相机，输出低分辨率 PNG 序列。

助手开始时应调用 `ping` 和 `get_document_state`，确认工程身份。批量场景操作尽量放进指定 `document_name` 的 `batch`。不要用重置整个工程替代局部编辑，不要对用户工程运行测试清理。

### 用户数据动画

1. 用 `add_user_data` 创建参数，或通过 `list_user_data` 读取现有参数。
2. 将返回的 `desc_id` 原样传给 `set_keyframe.path`，同时传对象 `handle`、`frame`、`value`。
3. 不要同时填写 `path` 和旧 `param_id/component`。完整路径包含 SDK 数据类型，不要凭数字猜测。
4. 用 `get_keyframes` 读回，再通过 `sample_transform` 或预览检查实际运动。写入一个控制器值不代表所有表达式和形变都正确。

完整路径接口并不支持所有动画类型。材质节点端口、点级动画、动画层、动作重定向仍需单独开发或验证。现有 REAL 轨道的 F-Curve 操作见下一节；新接口不沿用 0.4.0 的实机验收结论。

## 0.5.0 F-Curve 曲线控制

0.5.0 新增四个曲线工具，针对**已经存在的 REAL 数值轨道**，不自动创建轨道，也不是整套时间线或角色绑定系统。新增功能尚未安装或完成专项实机验收；接口及参数以 [TOOLS.md](./TOOLS.md) 和实际版本为准。

| 工具                      | 用途                                                 |
| ------------------------- | ---------------------------------------------------- |
| `get_fcurve`              | 读取曲线、关键帧和切线；可附加指定帧的曲线数值采样   |
| `edit_fcurve_keys`        | 按关键帧索引修改数值、插值、自动/手动切线及左右切线  |
| `transform_fcurve`        | 对全部或选定关键帧进行时间缩放/偏移、数值缩放/偏移   |
| `set_track_extrapolation` | 设置关键帧范围之前与之后的保持、线性、循环或往返行为 |

### 先定位，再修改

四个工具均需以下共同参数：

- `document_name`：精确、唯一的**当前活动工程名**。这些曲线工具不会为了匹配名称而隐式切换工程；不匹配时先停止检查。
- `handle`：已有动画对象或其他支持实体的定位句柄；重名时优先使用完整路径。
- `path`：从 `list_tracks` 读取并原样回传的完整 DescID，形如 `[[id, dtype, creator], ...]`；不要凭数字猜测。
- 或使用旧的 `param_id`，向量分量再加 `component: "x" | "y" | "z"`。不得同时填写 `path` 和旧选择器。
- 可选 `fps`：时间换算基准，默认工程帧率；同一组读写操作应使用同一个基准，不会因此修改工程本身的帧率。

先用 `get_fcurve` 确认轨道和关键帧索引，修改后再次读取并采样。`key_index` 是当前快照中关键帧的索引，不是帧号；时间变换可能改变排序，在 C4D 中手动编辑场景也可能令快照过时，因此不要继续沿用旧索引。

以下 JSON **只展示各调用的附加参数**，不是完整请求；调用时还须带上上述工程、句柄和轨道选择器。

### 读取和子帧采样

给 `get_fcurve` 附加：

```json
{
  "sample_frames": [0, 3.5, 6, 12, 24]
}
```

`sample_frames` 最多 300 项，支持小数帧。返回的 `left`/`right` 是 C4D 求值后的有效切线，包括自动模式计算的结果，不是隐藏的原始手柄值。采样读取的是该数值曲线，不等于整场景求值、蒙皮形变或物理模拟验收；检查对象最终运动仍需变换采样或预览。

### 手动切线与缓入缓出

确认曲线中第 0、1 个关键帧就是需要调整的两个端点后，可向 `edit_fcurve_keys` 传入：

```json
{
  "edits": [
    {
      "key_index": 0,
      "interp": "spline",
      "tangent_mode": "manual",
      "right": { "dt_frames": 3, "dv": 0 }
    },
    {
      "key_index": 1,
      "interp": "spline",
      "tangent_mode": "manual",
      "left": { "dt_frames": -3, "dv": 0 }
    }
  ]
}
```

这里把两个朝向区间内部的切线设为水平，是缓入缓出的起点示例。切线长度应根据实际关键帧间距选择，不是所有动画都适合 3 帧；修改后检查中间值，避免过冲或不希望的停顿。

- `value` 可修改关键帧数值；`interp` 可选 `linear`、`spline`、`step`。
- `tangent_mode` 可选 `auto` 或 `manual`。显式填写 `left`/`right` 时必须指定 `manual`，不能一边要求自动求切线一边指定手柄。
- 显式切换到 `manual` 会接管手柄：解除自动、夹制、自动权重、防过冲、切线角度/长度锁等干扰选项，并分离左右切线。需要保留这些辅助选项时不要执行手动接管。关键帧自身的时间锁、数值锁不会被强行解除。
- 未指定一侧的手柄会以本次读取到的有效切线为基线保留，不会直接暴露自动模式下隐藏的旧手柄；不支持的加权组合仍须实机单独核验。
- `dt_frames` 是切线相对于该关键帧的时间偏移，左侧必须小于 0，右侧必须大于 0；`dv` 是相对于关键帧值的偏移，不是绝对坐标。
- 曲线值使用参数本身的单位；旋转通常使用弧度，不是界面显示的角度数。

### 拉长动作或调整幅度

给 `transform_fcurve` 附加以下参数，可围绕第 0 帧将动作时长扩大为两倍，数值保持不变：

```json
{
  "time_scale": 2,
  "time_offset_frames": 0,
  "pivot_frame": 0,
  "value_scale": 1,
  "value_offset": 0,
  "value_pivot": 0
}
```

未提供 `key_indices` 时处理整条曲线；提供时只处理指定关键帧。换算为：

```text
新帧 = pivot_frame + (原帧 - pivot_frame) × time_scale + time_offset_frames
新值 = value_pivot + (原值 - value_pivot) × value_scale + value_offset
```

时间缩放必须大于 0，本版不支持时间反转。变换允许产生子帧；若新时间与其他关键帧碰撞则拒绝，不会悄悄覆盖或合并关键帧。只处理部分关键帧时尤其需要注意与未选中关键帧的碰撞。

变换保留自动/手动切线模式：手动切线随时间和值比例缩放；自动切线仍由 C4D 重新计算。因此，尤其在只变换部分关键帧时，不能保证整条曲线形状绝对不变，需要再次采样和预览。

如果手动键仍带有会干扰手柄变换的辅助选项，变换会提前拒绝；只有明确接受接管时，才先执行 `edit_fcurve_keys` 的 `tangent_mode: "manual"`，再重新读取和变换。不要自动解除用户的锁定来绕过错误。

### 关键帧范围外的行为

例如，给 `set_track_extrapolation` 附加：

```json
{
  "before": "constant",
  "after": "oscillate"
}
```

这表示第一帧之前保持端点值，最后一帧之后往返重复。`before` 和 `after` 可分别设置，选项为：

- `off`：关闭该侧的轨道外推。
- `constant`：保持端点值。
- `linear`：按端部趋势线性延伸。
- `repeat`：周期重复。
- `offset_repeat`：重复时累加每周期的首尾值差。
- `oscillate`：正向、反向交替往返。

外推只是曲线的求值规则，不会自动扩展工程时间范围、生成额外关键帧或增加序列渲染帧数。需要输出更多帧时，仍要明确设置相应范围。

### 曲线功能的限制

- 仅针对现有 REAL 数值轨道；整数、布尔、点级动画、动画层以及任意节点图动画不在本轮保证范围内。编辑工具也不处理耦合 XYZ 或时间轨道。
- 每条曲线最多处理 1000 个关键帧；采样最多 300 项。超过限制应停止并重新设计处理方式，不要靠不断重试或只缩小选集绕过整条轨道的上限。
- 帧位置、时间偏移、时间枢轴、切线时间偏移及采样帧的绝对值不得超过 1,000,000；`time_scale` 必须大于 0 且不超过 1,000,000。变换结果也必须通过边界检查。
- 支持子帧读取/变换，不代表所有旧关键帧工具也接受小数帧；例如旧 `set_keyframe.frame` 仍要求整数。
- `get_keyframes` 现已保留小数帧位置；`delete_keyframe` 的整数帧或范围按准确时间比较，不会把相邻子帧取整后误删。
- 修改前保存副本；先读取、再小范围编辑、再读回。离线测试通过不能替代安装后在隔离场景中的曲线形状和撤销验证。
- 编辑先在脱离工程的轨道副本上验证，再记录撤销并写回。写回结果异常时尝试恢复原副本；如果恢复也失败，会明确报告可能部分修改，不能继续当作成功或自动重试。

专项实机命令为 `npm run test:live:fcurves:2025`，不是日常启动命令。它要求已安装 0.5.0、对应能力标志和明确的实机测试授权，只创建一个隔离测试工程；如果原活动工程完全空白则提前拒绝，防止 C4D 自动替换空白工程。本轮只准备了该测试，尚未执行，不能把“测试脚本存在”视为实机通过。

## 对象引用

`set_params` 中的一项可以写成：

```json
{
  "path": 12345,
  "value": { "link": { "kind": "object", "path": "/目标对象" } }
}
```

`12345` 只是示意，必须换成从 `describe` 读取的真实引用参数路径。桥接器会核对真实参数类型；普通数值参数不能接收对象引用。通过 `{ "link": null }` 才能明确清空引用，找不到对象不会自动变成空引用。

## PNG 序列

先准备名称唯一的工程和 Redshift RenderData，设置 PNG 格式、合适的分辨率及采样，并明确关闭该设置中的 AOV。输出目录的父目录必须存在，但新任务的输出目录必须不存在。

```json
{
  "document_name": "机械臂",
  "render_data_name": "RS_Sequence",
  "output_directory": "D:\\renders\\arm_take_001",
  "frames": [0, 2, 4, 6, 8, 10, 12],
  "force": true
}
```

将此参数传给 `rs_render_sequence`，保存返回的 `job_id`。随后用 `rs_sequence_status` 查询：

- `running`：逐帧渲染；`current_frame` 为当前帧。
- `cancelling`：已收到停止请求，等待在途帧结束。
- `cancelled`：未完成的后续帧没有继续调度。
- `completed`：所有计划帧均已返回并通过 PNG 结构、CRC、尺寸及文件大小检查。
- `failed`：明确失败，保留已生成文件，不自动重试。
- `uncertain`：连接中断或超时，C4D 可能仍在渲染；不要关闭渲染中的工程或自动重试。

终态还须等待 `settled: true`，表示本进程的收尾写盘已结束。它不代表 `uncertain` 状态下 C4D 已停止。

`rs_sequence_control` 接收 `job_id` 和 `action: "cancel"` 或 `"resume"`。只有正常取消的任务能续跑，续跑前校验已完成文件的 SHA-256。渲染或暂停期间不要修改场景，否则前后帧可能来自不同版本的场景。

### 明确限制

- 每任务 1–300 个不重复帧，非负整数，按帧号升序输出；每 MCP 进程最多保留 20 个任务记录，只同时运行一条序列。
- 本版为 PNG 主图序列，不含 AOV 序列、视频编码、Team Render、跨机器农场、未烘焙模拟或跨进程任务恢复。
- `manifest.json` 和各帧文件会保留在输出目录。控制与续跑必须使用同一个 MCP 服务器进程；重启后不会自动恢复任务。
- 停止只阻止后续帧，不会强行中断 C4D 当前帧。渲染可能占用 C4D 主线程，因此不要同时操作目标工程。
- 不覆盖已有输出。失败帧需要人工检查；不会自动删除可疑文件或不断重试。
- 多个 MCP 客户端/进程之间没有全局队列锁，请勿从多个客户端同时启动序列。
- 不承诺无损模拟缓存恢复、复杂角色变形、透明通道或高位深 EXR 制作质量。

## 测试与安装

```powershell
npm ci
npm run build
npm test
python -m unittest discover -s tests/python
npm run check
npm run install:c4d -- --dry-run
```

普通 `npm test` 和 CI 只运行离线测试，不连接 C4D。审阅安装路径、备份并完全退出 C4D 后，才运行安装器的 `--install`；重新启动 C4D 和 MCP 服务器以加载两侧更新。不要在运行中覆盖插件或热加载模块。

明确允许占用 C4D 后，单工程专项命令为 `npm run test:live:workflow:2025`。它需要桥接器可用、安全门和精确版本符合要求，且只创建一个隔离测试工程；成功或确定失败后清理。如果渲染结果未知则保留现场，不强制关闭。测试跳过不等于通过。

## 后续开发顺序

1. 扩充同一机械场景的控制器和约束验收，再增加更长及更高分辨率序列。
2. 独立补骨骼创建、蒙皮与权重读写、IK/FK、Pose Morph 的专用操作和形变检查。
3. 扩展 UV、动画烘焙、模拟缓存、AOV 序列及可靠的跨进程恢复。

任意 Python 默认关闭；开启它不等于这些功能已经实现、可撤销或被验证。实际时间/求值与渲染处理依据 [Maxon BaseDocument SDK](https://developers.maxon.net/docs/py/2025_3_0/modules/c4d.documents/BaseDocument/index.html) 和 [RenderDocument SDK](https://developers.maxon.net/docs/py/2025_3_0/modules/c4d.documents/index.html)。
